# شرح المشروع حتة حتة (للمناقشة)

## 1) الفكرة في جملة واحدة
مساعد ذكي بيجاوب على أسئلة الطلاب من **ملفات PDF** و **جداول Google Sheets**، وبيفتكر الكلام اللي اتقال في نفس الشات، فلو سألته "مين بيدرّس Machine Learning؟" وبعدها "إيه المتطلبات السابقة بتاعته؟" هيفهم إن "بتاعته" يقصد بيها الكورس.

الداتا عبارة عن جامعة وهمية: لائحة أكاديمية + دليل خدمات (PDF) وجدول مقررات + جدول رسوم (Sheets).

## 2) ليه RAG؟
الـ LLM لوحده مش عارف لائحة جامعتك، وممكن "يألف" إجابة. الـ RAG (Retrieval-Augmented Generation) بيحل ده بـ 3 خطوات: نبحث في بياناتنا عن الفقرات المناسبة للسؤال، نديها للـ LLM مع السؤال، ونطلب منه يجاوب منها بس. ده بيقلل الهلوسة ويخلي الإجابة قابلة للتحقق (بنطلّع المصدر).

## 3) شرح كل ملف

### `src/loaders.py` - تجهيز البيانات (Step 1)
- **PDF**: `pypdf` بيقرأ كل صفحة، وبنحولها لـ `Document` فيه النص + metadata (اسم الملف ورقم الصفحة) عشان نقدر نعمل citation.
- **Google Sheets**: الكود بيحوّل لينك الشيت لرابط تصدير CSV (`/export?format=csv&gid=..`) فمش محتاجين OAuth، بس الشيت لازم يكون "Anyone with the link can view". ولو مفيش لينكات بيقرأ ملفات `data/sheets/*.csv`.
- **تحويل الجدول لنص**: كل صف بقى جملة بالشكل `Course Name: Machine Learning | Instructor: Dr. Sara Khalil | ...`. السبب إن الـ embedding بيفهم النص مش الجداول، وكل صف لازم يكون "حقيقة" كاملة بذاتها. وكمان بنضيف Document ملخص لكل شيت (أسماء الأعمدة وعدد الصفوف).

### `src/indexer.py` - الـ Embeddings و FAISS (Step 2)
- **Chunking**: صفحات الـ PDF بتتقسم بـ `RecursiveCharacterTextSplitter` (800 حرف، overlap 120). الـ overlap عشان الجملة اللي على حدود القطعتين ماتضيعش معناها. صفوف الشيت **ما بتتقسمش** لأنها صغيرة.
- **Embeddings**: تحويل كل قطعة لمتجه أرقام معناه قريب من معنى النص. الافتراضي HuggingFace `paraphrase-multilingual-MiniLM-L12-v2` (مجاني، شغال محلي، **بيفهم عربي وإنجليزي**)، وممكن OpenAI بتغيير سطر في `.env`.
- **FAISS**: مكتبة من Meta بتدور على أقرب المتجهات بسرعة. بنحفظ الـ index على الديسك مع `manifest.json` فيه fingerprint للداتا والإعدادات، فلو الداتا أو الموديل اتغيروا بيعمل rebuild لوحده، وغير كده بيحمّله في ثواني.
- فيه `HashingEmbeddings`: embedding أوفلاين بسيط (بيطابق كلمات بس) لتشغيل الاختبارات من غير إنترنت. **مش للاستخدام الحقيقي**.

### `src/memory.py` - الذاكرة (Step 4)
- **BufferMemory**: بتخزن كل الرسايل (Human/AI) من أول الشات. بسيطة ودقيقة، بس بتكبر مع الوقت.
- **SummaryBufferMemory** (اختيارية): بتحتفظ بآخر N أدوار كما هي، وأي حاجة أقدم بتتلخص بالـ LLM في ملخص متجدد. بتوفر tokens في الشاتات الطويلة.
- كتبتها بـ `langchain_core` مباشرة لأن `ConversationBufferMemory` القديمة اتشالت/اتهجرت في إصدارات LangChain الجديدة. نفس الفكرة بس من غير الاعتماد على API مهجور. ولو دكتورك قال "ليه مستخدمتش ConversationBufferMemory؟" ده الرد.

### `src/rag_chain.py` - قلب المشروع (Step 3)
لكل سؤال بيحصل:
1. **Condense (إعادة صياغة)**: لو فيه تاريخ، الـ LLM بيحوّل "إيه المتطلبات بتاعته؟" لسؤال مستقل "ما هي المتطلبات السابقة لكورس Machine Learning؟". ده **أهم جزء في التعامل مع الـ follow-up**، لأن البحث في FAISS بيشتغل على نص السؤال، ولو بحثنا بـ "بتاعته" هنجيب نتايج غلط.
2. **Retrieve**: `similarity_search` بترجع أقرب `top_k=4` قطع.
3. **Generate**: الـ prompt فيه قواعد: جاوب من الـ context بس، لو مش موجود قول جملة ثابتة "I don't know based on the provided documents."، جاوب بلغة السؤال، اذكر المصدر. وبنمرر تاريخ الشات + الملخص (لو موجود) عشان الـ LLM يفهم السياق.
4. **Save**: السؤال والإجابة بيتحفظوا في الذاكرة.
- بنرجّع `Answer` فيها الإجابة والمصادر والسؤال المعاد صياغته (مفيد جدًا للـ debugging والعرض).

### `src/llm.py`
Factory بيختار OpenAI / Gemini (فيه free tier) / Ollama (محلي) من `.env`. وفيه `MockChatModel` أوفلاين (مش ذكاء حقيقي) عشان نختبر التدفق كله من غير API key.

### `app.py`
واجهة سطر أوامر: `/history` `/sources` `/reset` `/exit`، و`--rebuild` `--offline` `--memory`.

## 4) الاختبار والتقييم (Step 5)
- `tests/test_pipeline.py` (12 اختبار): تحميل PDF والشيت، تحويل لينك Google، الـ chunking، كاش الـ index، الذاكرة (Buffer + Summary)، الـ follow-up، سؤال "إيه أول سؤال سألته؟"، ورفض الأسئلة الخارج النطاق.
- `eval/evaluate.py` على 24 سؤال في 5 فئات، والمقاييس:
  - **retrieval_hit**: هل القطع المسترجعة جاية من الملف المتوقع؟
  - **context_recall**: هل الكلمات المفتاحية للإجابة موجودة في القطع المسترجعة؟ (بيفصل مشكلة الـ retrieval عن مشكلة الـ LLM)
  - **answer_accuracy / answer_pass**: نسبة الكلمات المتوقعة في الإجابة، والنجاح الصارم.
  - **refusal_ok**: هل رفض الإجابة على سؤال مالوش علاقة بدل ما يألف؟
  - **judge_relevance** (اختياري `--judge`): LLM بيقيّم الإجابة من 1 لـ 5.
- **مهم تقوله بصراحة**: النتايج اللي جوه الملف اتعملت بالـ mock الأوفلاين (بتثبت إن الكود والـ retrieval والذاكرة شغالين، بس مش بتقيس جودة LLM حقيقي، وفيه سؤال S01 فشل عشان الـ mock بيختار الجملة غلط). **شغّل التقييم بمفتاحك وحط الأرقام الحقيقية في العرض**.

## 5) أسئلة متوقعة في المناقشة وإجاباتها
- **إيه الفرق بين Buffer و Summary memory؟** Buffer بيحفظ كل حاجة (دقيق لكن بيكبر ويغلّي)، Summary بيحفظ آخر N أدوار + ملخص للأقدم (أرخص لكن ممكن يفقد تفاصيل).
- **ليه بتعمل condense قبل الـ retrieval؟** عشان أسئلة المتابعة فيها ضمائر ("ده"، "بتاعه") والـ embedding مش بيفهمها من غير سياق.
- **ليه الشيت صفوفه ما بتتقسمش؟** كل صف حقيقة كاملة وصغيرة؛ تقسيمه بيفصل اسم الكورس عن المدرّس.
- **إيه اللي بيمنع الهلوسة؟** الـ prompt بيجبر على الإجابة من الـ context بس، وجملة رفض ثابتة، و temperature=0، وعرض المصادر.
- **إيه نقاط ضعف الـ RAG هنا؟** أسئلة التجميع ("كام كورس في المستوى 3؟")، الجداول جوه الـ PDF، الـ PDF الممسوح ضوئيًا (محتاج OCR)، و top_k صغير ممكن يفوّت إجابة موزعة على قطع كتير.
- **إزاي تحسّنه؟** hybrid search (BM25 + vectors)، reranker، MMR للتنويع، metadata filtering (مثلاً البحث في الشيت بس)، OCR، وإضافة tool لحساب التجميعات على الجدول (Agent).
- **ليه HuggingFace multilingual؟** عشان الطالب يسأل بالعربي والداتا إنجليزي ويشتغل برضه.
- **إزاي تغيّر الداتا؟** حط ملفات في `data/` أو لينكات في `SHEET_URLS` وشغّل `--rebuild`.

## 6) تشغيل سريع
```
pip install -r requirements.txt
cp .env.example .env     # حط OPENAI_API_KEY (أو LLM_PROVIDER=gemini/ollama)
python app.py
python -m eval.evaluate  # التقييم بالـ LLM الحقيقي
```
